# DocLite 开发流程 · 一页纸操作手册

> 打印出来贴在显示器旁边。用到 2026-11-06 之后新增的命令。

---

## 你现在只需要记 4 个命令

在项目目录 `/home/zhengyz/文档/doclite` 下执行。

| 命令 | 什么时候用 | 干什么 |
|---|---|---|
| `npm run handoff` | **要派活给星辰时** | 列出所有待办，挑完后生成指令包 |
| `npm run smoke` | 星辰说"改完了" | 检查它是不是真改好了（你要看结果） |
| `npm run status` | 想知道"现在还有什么没修" | 看问题清单和项目状态 |
| `npm run verify` | **准备发版前** | 一键体检：能不能发版 |

---

## 完整流程（4 步）

### 第 1 步 · 派活

```bash
npm run handoff
```

会列出所有待办（编号 + 问题 + 状态）。挑你要这轮做的，记下编号。

```bash
npm run handoff R-031 R-032
```

生成完整指令包 → **全选复制** → **粘贴给星辰超级智能体**。

做新功能不用编号：

```bash
npm run handoff -- --task "给 Markdown 预览加目录侧边栏"
```

> **关键变化**：以前你得手写"背景是什么、约束是什么、验收标准是什么"。
> 现在指令包自动带上这些，星辰自己去读 `docs/STATE.md`（历史决策）和 `docs/TASKS.md`（问题清单）。
> **你不再需要当搬运工。**

---

### 第 2 步 · 星辰干活

星辰会自己读文件、改代码、跑 `npm run smoke`。

**你什么都不用做。** 除非它来问你，那通常说明它没读 `docs/STATE.md`。

---

### 第 3 步 · 验收

星辰说改完了，你跑一次：

```bash
npm run smoke
```

看最后一行：

| 结果 | 意思 | 你该做什么 |
|---|---|---|
| `失败 0` | 通过 | 往下走 |
| `失败 N`（N>0） | **它改坏了** | 把它贴回给星辰：「smoke 失败，修一下」 |
| 有 ⚠ 警告 | 正常，那些是老问题 | 忽略 |
| L4 跳过 | 本机环境限制 | 忽略，在开发机上会跑 |

---

### 第 4 步 · 发版

```bash
npm run verify
```

- 退出码 0 → 可以发版
- 退出码 1 → 看它说缺什么，处理完再跑

然后照旧打 tag 发版，CI 自动构建三个平台。

## 三份文件在哪

| 文件 | 是什么 | 谁维护 |
|---|---|---|
| `docs/TASKS.md` | **问题清单**。157 条，每条有状态（待修/已修/待验…） | 星辰改完自己更新 |
| `docs/STATE.md` | **决策记录**。39 条，写清"为什么这么做" | 星辰要改决策时才动 |
| `docs/reviews/` | 10 篇历史审查报告原文 | 只读，归档 |

**Obsidian 现在只是"人读的视图"，不用再往里搬东西了。** 那些历史报告已经复制进仓库 `docs/reviews/`。

## 什么时候用哪个命令

```
有想法要派活      →  npm run handoff -- --task "你的想法"
要修已知问题      →  npm run handoff R-031 R-032
星辰说改完了      →  npm run smoke
不知道剩什么没修  →  npm run status
准备发版          →  npm run verify
```

## 常见问题

**Q：`npm run smoke` 报 electron 版本不一致？**
A: 重新下载 Electron 二进制：
```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js
```

**Q：L4 总是被跳过？**
A: 本机内存不够（渲染进程 OOM）。不影响其他三层。要跑 L4 就在有显示环境的机器上跑。

**Q：星辰说"要我把审查报告读一遍"，能省吗？**
A: 指令包已经告诉它读哪些文件。它读完 `docs/STATE.md` 和 `docs/TASKS.md` 就够了 —— 审查报告在 `docs/reviews/`，只有需要细节时才翻。

**Q：我能自己改 `docs/TASKS.md` 吗？**
A: 能。加新问题、划掉已解决的都行。但**别删历史条目** —— 那是"为什么当初这么做"的证据。
