### H1｜问题 2：20% 热区会让"左五分之一区域"无法滚轮滚动（并且无法触摸滑动）

**定位**：`src/App.jsx:119`（`w-[20%]` 的固定定位蒙层）、`src/index.css:181-190`（`pointer-events: auto`）

**机制**：这个 div 是 `fixed` 蒙层，`pointer-events: auto`，与预览滚动容器是**兄弟节点**，不在它的祖先链上。滚轮事件的 target 落到蒙层后，浏览器会去找"最近的**可滚动祖先**"——蒙层上面只有 `overflow-hidden` 的容器和 body，所以**什么都不滚**。同理触摸设备上的拖动也无效。

`pointer-events: none` 之前是 8px 宽，没人感知；现在变成窗口的 20%（1440px 窗口 = 288px），用户阅读时鼠标随手停在左侧就会遇到"滚轮没反应"，而且蒙层还带 `cursor: default`（PDF 上应该出现文本光标的地方变成箭头），有明确的错误暗示。

注释里写的"吃掉点击（选词/链接）"是已知代价，但**滚动失效没被记录，也不该接受**。

**建议（推荐，能同时消除点击与滚动两个代价）**：删掉蒙层，改成窗口级 mousemove 判定。语义完全满足"鼠标移到界面左边 20% 就滑出"，且不占用任何鼠标事件：

```jsx
// App.jsx：删除 {immersive && <div className="immersion-hotzone ..."/>}
useEffect(() => {
  if (!immersive) return
  const onMove = (e) => {
    if (e.clientX > window.innerWidth * 0.2) return
    cancelHide()
    if (!sidebarOpenRef.current) setSidebarOpen(true)
  }
  window.addEventListener('mousemove', onMove, { passive: true })
  return () => window.removeEventListener('mousemove', onMove)
}, [immersive, cancelHide])
```
（`sidebarOpenRef` 用 ref 镜像 `sidebarOpen`，避免每次移动都 setState；原有 `onMouseLeave → scheduleHide` 保持不动。）

如果坚持保留蒙层，最低限度也要加 `pointer-events: none`（那它就只是个装饰，`onMouseEnter` 也失效了，等于必须改 mousemove），或给蒙层加 `onWheel` 手动把 `deltaY` 转发给预览滚动容器（后者要拿到具体容器的 ref，成本更高、且修不了触摸）。

### H2｜问题 1：中文副标题含「：」「、」「，」或超过 40 字时，原 bug 原样复现

**定位**：`src/utils/converters.js:836-841`（`looksLikeTitleLine` 的标点/长度白名单），分支在 `:960`

```js
if (/[。！？；，、：;,.!?]/.test(s)) return false   // ← 全角冒号、顿号、逗号都被挡掉
if (!s || s.length < 2 || s.length > 40) return false
```

中文书名/章名的副标题**极常见**带冒号或顿号（「不断缩水的鱼：货币的隐喻」「鱼、货币与增长」）。这类行不命中 `looksLikeTitleLine` → 落到 `else` → `flushSubtitle()` 把收集状态关掉 → 紧随其后的大写英文行全部进正文。

**实测**（把 `converters.js` 的私有函数导出后，按 `:955-970` 的分支逻辑复刻跑样例）：

| 场景 | 输出 |
|---|---|
| A 报告样本「不断缩水的鱼就像货币一样」 | `<h3>第十章</h3><p>不断缩水的鱼就像货币一样 在太平洋的某个岛上…</p>` ✅ 英文已删 |
| B 副标题带全角冒号「不断缩水的鱼：货币的隐喻」 | `<p>不断缩水的鱼：货币的隐喻 **HOW AN ECONOMY GROWS AND WHY IT CRASHES** 正文开始。</p>` ❌ 复现 |
| C 副标题带顿号「鱼、货币与增长」 | `<p>鱼、货币与增长 **HOW AN ECONOMY WHY IT CRASHES** 正文开始。</p>` ❌ 复现 |
| D 副标题 41 字（超长） | `<p>… **HOW AN ECONOMY WHY IT CRASHES** 正文开始。</p>` ❌ 复现 |

**最小改法**（二选一）
1. 放宽白名单：只挡真正的句读 `[。！？；]`，允许 `：、，`（这类标点出现在"紧跟章节标题的短行"里，几乎不可能是正文句），并把长度上限提到 60；
2. 更稳的做法：别再用"像不像标题"来维持状态，改成**固定窗口**（见 M1 的方案），标点/长度都不再是判定条件。

### M1｜问题 1：`subtitleActive` 没有窗口上限，连续短中文行会把状态带进正文，误删正文的大写英文行

**定位**：`src/utils/converters.js:916`、`:957-966`

状态只有遇到"不命中 TL 且不是英文副标题"的行才会结束。而一页里的短中文行（小标题、要点、诗歌式断行）都可能连续命中 `looksLikeTitleLine`，于是 `subtitleActive` 一路为真，后面正文里出现的大写英文行就被当成副标题删掉。

**实测 E**：`第十章` → `第一节要点`（被判为 h3）→ `要点一` → `要点二` → `要点三` → **`GDP GROWTH`** → `正文。`
输出：`<h3>第一节要点</h3><p>要点一 要点二 要点三 正文。</p>` —— **`GDP GROWTH` 被静默删除**。

**建议**：把"永远为真"改成"有限窗口"，同时天然解决 H2：

```js
let postHeading = 0            // 标题后仍处于副标题过滤窗口的“输出行”数
...
if (looksLikeHeading(item)) { ...; postHeading = 3 }
else if (postHeading > 0 && looksLikeEnglishSubtitle(trimmed)) { /* 丢弃，不递减 */ }
else { if (postHeading > 0) postHeading--; flushPara?; para.push(trimmed) }
```
窗口按"真正输出出去的行"递减，最大误删范围就是标题后的 3 行，且 3 行足够覆盖"中文标题 1-2 行 + 英文副标题 2-4 行"的真实版式。

### M2｜问题 1：中文章名副标题被并进正文首段，不是一个独立段落

**定位**：`src/utils/converters.js:960-963`（`para.push(trimmed)`，没有 `flushPara()`）

} else if (subtitleActive && looksLikeTitleLine(trimmed)) {

  flushPara()

### M3｜问题 3：macOS 手动更新面板没有"重新检查"，侧栏的「检查更新」会一直重开旧面板

**定位**：`src/useUpdater.js:80-84`（`openDialog` 只在 `phase === 'idle'` 时 `check()`）、`UpdateDialog.jsx:66-77`（手动面板只有"关闭/前往下载"）

macOS 上 `download()` 抛错后 `phase === 'error'`。此后：
- 侧栏按钮 → `openDialog()` → 因为 `phase !== 'idle'`，**不会重新检查**，只是把同一个"手动更新"面板再打开一次；
- 面板里又没有"重试/重新检查"，用户想确认是否有更新只能重启应用。

（非 macOS 的错误态有「重试」按钮，所以只有 mac 这条路径会卡住。不是死锁，但属于状态机缺口。）

**最小改法**：`openDialog` 改成 `if (phase === 'idle' || phase === 'error') check()`；或在手动面板加一个「重新检查」文字按钮（复用 `check`）。

### 问题 1（状态机完备性）
- **状态不跨页**：`subtitleActive` / `subtitleLines` 声明在页循环内（`converters.js:916-917`，循环始于 `:860`），每页重新初始化 → 审查点"状态泄漏到下一页"**不成立**。
