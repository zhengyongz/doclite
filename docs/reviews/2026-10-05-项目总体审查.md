## 🔴 较重要（建议优先关注）

1. **转换时内存峰值高，长文档易 OOM**
   - `converters.js` 的 `elementToPdf`：先把**所有页**的 html2canvas（scale=2）canvas 攒在内存里，再用 `toDataURL('image/png')`（base64，体积再涨 ~33%）逐页塞给 jsPDF。Word 长文档或大 Excel 会内存暴涨。
   - `PdfRenderer.jsx` 的 `renderedPages` state 只增不减：翻过的页 canvas 永久驻留，几百页的 PDF 内存持续增长（虚拟滚动只卸载了 DOM 节点，canvas 对象没释放）。

2. **Excel 大表两个隐患**
   - `XlsxRenderer.jsx` 第 58 行与 `xlsxToPdf` 里的 `Math.max(...rows.map(...))`：行数超过约 10 万时 spread 参数超限，直接抛 `RangeError: Maximum call stack size exceeded`，应改为 reduce 循环。
   - 表格全量渲染无虚拟化，几万行会卡死 UI；`cellStyles: true` 也明显拖慢解析且样式并未被使用。

3. **Azw3Renderer 封面 blob URL 泄漏**
   清理 effect（空依赖数组）捕获的是**首次渲染**的 `bookData`（此时是 null），所以 `coverUrl` 永远不会被 revoke。

4. **XSS 风险**：`Azw3Renderer` 用 `dangerouslySetInnerHTML` 直接渲染电子书解出的 HTML，未做任何消毒。恶意构造的 MOBI 可注入脚本，Electron 渲染进程会执行。建议 DOMPurify 清洗。

5. **Electron 安全加固不全**（对照官方安全清单）
   - `webPreferences` 未开 `sandbox: true`（preload 只用了 ipcRenderer，完全可开）；
   - 没有 `setWindowOpenHandler` 拦截新窗口、没有 `will-navigate` 防护；
   - `index.html` 无 CSP；
   - 小矛盾：`after-install.sh` 给 chrome-sandbox 设 SUID，而 `main.cjs` 和 deb 配置又禁用了沙箱，SUID 实际无意义。

6. **异步任务无取消机制**：切换文件时旧的解析/渲染 Promise 不 abort，可能状态竞态 + objectURL 泄漏（`PptxRenderer` 的图片 URL 靠 effect 清理，快速切换文件时闭包可能拿到旧值）。
