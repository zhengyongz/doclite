### H1｜英文界面下，转换组件安装/卸载失败会整段显示中文（完全绕过了翻译层）

**定位**
- `src/components/ConvertPanel.jsx:161-163`（未安装态）、`245-247`（已安装态）：`{compError}` 直接渲染，**既没有 t() 也没有 ts()**
- 错误来源：`src/useConverters.js:51`、`:71` —— `setError((r && r.error) || t(...))`，其中 `r.error` 是主进程原样中文
- 中文串来自 `electron/converters-component.cjs:100/101/123/126/128/129/144/148/152/231/234/237/268`，例如
  - `组件包含不允许的文件：xxx`
  - `组件文件解压失败：xxx（...）`
  - `组件需要主程序 x 及以上，请先升级应用`
  - `当前版本（v x）暂无匹配的转换组件包，请稍后再试或升级应用`

**影响**：英文界面用户点「Install converter component」，一旦失败（网络、sha256、zip 损坏、版本不匹配——都是**常见**路径），面板里会出现一条完整中文错误。这是英文用户最容易撞见中文的场景。

**最小改法**
1. 两处渲染改为 `{ts(compError)}`；
2. 在 `src/i18n.jsx` 的 `ts()` 里补前缀规则（这比逐条枚举更省事）：
   ```js
   const compErr = /^(组件[^：]*|当前版本（v[^）]*）[^：]*)：([\s\S]*)$/.exec(s)
   ```
   更稳的做法是主进程改为返回 `{ code, detail }`，渲染层按 code 取文案（DEVLOG 已把这条列为后续方向，建议这次至少把 `ts()` 用上）。

### H2｜中文界面下 AZW3 章节渲染失败会显示原始 key `renderer.azw.sectionFailed`

**定位**
- 使用处：`src/components/renderers/Azw3Renderer.jsx:102`，经 `:319` 的 `dangerouslySetInnerHTML` 直接输出
- 缺项：`src/i18n.jsx` 的 `zh` 字典（32-176 行）**没有** `renderer.azw.sectionFailed`；只有 `en` 有（`:251`）

**实测（把 i18n 模块反编译后在 Node 里跑）**
```

```
即中文用户看到的是字面量 key，而不是「本章节渲染失败」。

**最小改法**：在 `zh` 字典补一条（建议顺手去掉内联 style，见 L4）：
```js
'renderer.azw.sectionFailed': '本章节渲染失败',
```
组件侧改成 `<p className="...">{t('renderer.azw.sectionFailed')}</p>`，不再走 HTML 字符串。

### M2｜`useUpdater.js` 整文件没接入 i18n，两处兜底仍是硬编码中文；且 3 个已备好的英文键成了死键

**定位**
- `src/useUpdater.js:28`：`setErrorMsg(r.error || '检查失败')`
- `src/useUpdater.js:104`：`setInstallNote(r?.error || '安装未完成')`
- 这两个文件恰好**不在本次改动列表里**（i18n 覆盖了 17 个组件，漏了它）
- 已定义但零引用的键：`updater.checkFailed`、`updater.downloadInProgress`、`updater.installIncomplete`（`grep` 实测引用数 0）

**影响**：英文界面下检查更新失败（无 error 详情时）显示「检查失败」；一键安装未完成显示「安装未完成」。

**最小改法**：`useUpdater` 里 `const { t } = useI18n()`（它在 `I18nProvider` 内，可直接取），
```js
setErrorMsg(r.error || t('updater.checkFailed'))
setInstallNote(r?.error || t('updater.installIncomplete'))
```

**附带**：`src/useUpdater.js:69` 用 `r.error !== '下载已在进行中'` 做**中文串比较**控制 UI 状态。现在能工作，但一旦主进程文案改英文/加标点就静默失效（会把正常互斥当错误弹红）。建议主进程返回 `code: 'BUSY'` 之类的机器码。

### M3｜切换语言后，已经"捕获成中文"的文案不会跟着变（含一处真实闭包 bug）

**定位**
1. **真闭包 bug**：`src/App.jsx:56` 的 `useEffect(..., [])` 只注册了首次渲染的 `loadOpenFile`，函数体在 `:35`、`:46` 用了 `t`。切到英文后再通过文件关联打开一个不支持的扩展名 → 仍报中文。
2. `src/components/renderers/MdRenderer.jsx:54`、`:59`：`notices` 存的是**翻译后的字符串**，切语言不会重算（大文件截断提示会一直是旧语言）。
3. `src/components/renderers/Azw3Renderer.jsx:102` 的 `sectionContents` 同理。
4. `ErrorToast` 正在显示的 toast 同理（生命周期短，可接受）。

**最小改法**
- `App.jsx`：加 `const tRef = useRef(t); tRef.current = t`，函数体改用 `tRef.current(...)`（与现有 `setFileRef` 同款写法，改动 3 行）；
- `MdRenderer`：`notices` 改存 **key+变量**（如 `{key:'renderer.md.noticeTruncate', vars:{...}}`），渲染时再 `t()`；
- Azw3：失败占位改为渲染时判断（配合 H2）。

> 注意：**不要**简单把 `t` 加进渲染器 `useEffect` 的依赖——那会导致切语言时整篇文档重新解析（PDF/Word 大文件代价很高）。当前"不重解析"的行为是对的，只是文案层需要单独处理。

### M4｜`<html lang>` 不随语言切换（a11y）

**定位**：`index.html:2` 固定 `lang="zh-CN"`；`src/i18n.jsx:424-426` 的 effect 只改了 `document.title`。

**影响**：英文界面下读屏仍按中文语音规则朗读；浏览器拼写检查、断词、字体回退也会用错语言。Electron 里影响小于 Web，但属于标准 i18n 必做项。

**最小改法**（同一 effect 里加一行）：
```js
document.documentElement.lang = lang === 'en' ? 'en' : 'zh-CN'
```

### M5｜英文缺 key 时静默回退中文，没有任何告警或守卫

`resolve()`（`src/i18n.jsx:372-378`）的语义是：
- `zh`：`zh[key] ?? key`（**不回退 en**，符合"中文界面不冒英文"的预期 ✅）
- `en`：`en[key] ?? zh[key] ?? key`（缺 key 会**静默显示中文**）

这个回退策略本身合理（宁可显示中文也别显示 key），但它是"静默"的——本次 H1/H2 就是这么漏过去的。

**建议**（零依赖，两行）：
```js
if (import.meta.env.DEV && lang === 'en' && en[key] === undefined && zh[key] !== undefined)
  console.warn('[i18n] missing en key:', key)
```
再配一个 `scripts/check-i18n.mjs`（30 行，扫描 `t('...')` 字面量对比字典），挂到 `npm run build` 前。这样下次改文案不会靠人眼发现。

## ✅ 确认无问题（逐条对应审查要点）

1. **字典完备性**：所有 `t('...')` / `ts('...')` 字面量 key 在 `en` 中**全部存在**；`zh` 仅缺 `renderer.azw.sectionFailed` 1 条（即 H2）。
2. **`t()` 未收录 key 安全**：实测返回 key 本身，不抛错、不返回 `undefined`；`t(undefined)` 返回 `undefined` 且被 `||` 兜住（`UpdateDialog.jsx:61`）。
3. **zh 不回退 en**：实测 `t('zh','renderer.azw.sectionFailed')` 返回 key 而非英文，符合"中文界面不冒英文"的设计。
4. **`ts()` 两条正则**：实测
   - `文件大小 (123.4 MB) 超出限制（Word 最大 100 MB）` → `File size (123.4 MB) exceeds the limit (100 MB max for Word)`
   - `不支持的格式 ".txt"，仅支持 .docx / .pdf` → `Unsupported format ".txt"; only .docx / .pdf are supported`
   - 未收录原样返回，无异常。**正则本身没写错**，问题只是"调用点没用它"（M1 前半）。
5. **React 侧（审查要点 4）**：
   - Context value 用 `useMemo([lang])`，切换时只产生**一次**新引用，消费组件各重渲一次，属预期成本；
   - 渲染器 effect 依赖是 `[currentFile, ...]`，**不随语言变化重跑** → 切语言不会重新解析 PDF/Word，无"重复加载"；
   - 未发现"切语言后不重载导致内容错误"的情况（内容本身与语言无关）。
6. **a11y / 拖动区（要点 5）**：Header 按钮 `title` + `aria-label` 双齐全；`no-drag` 类在 `src/index.css:166` 有定义，且 `app-region: drag` 只在 `html.platform-darwin .app-header` 生效 → macOS 上按钮可点，其他平台无副作用。
7. **持久化与启动（要点 6）**：`loadLang` 先读 `localStorage['doclite-lang']` 并校验仅接受 `zh/en`，非法值/首次访问回退 `detectLang()`；`setLang` 同步写盘；`document.title` 随 lang；刷新后保持。
8. **构建回归（要点 7）**：`vite build`（输出重定向到 `/tmp/doclite-build-check`）**通过**，61 modules，14.26s；17 个改动的 js/jsx 文件 esbuild 语法检查全部通过；i18n 无新增依赖、`package.json` 未改。
