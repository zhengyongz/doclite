## 🔴 高优先级

### H1. `updater:open-installer` 未限定目标路径，可对渲染层传入的任意路径执行打开操作

- **定位**：`electron/updater.cjs:231-239`
- **问题**：IPC handler 直接信任渲染层传来的 `filePath`：Windows 上 `shell.openPath(filePath)` 会执行任意路径下的可执行文件（.exe/.bat/.msi 等），Linux 上 `showItemInFolder` 也会暴露任意位置文件。虽然当前渲染层是自有代码，但一旦渲染进程被攻破（本项目直接用 `dangerouslySetInnerHTML` 渲染不受信电子书内容，攻击面真实存在），这条 IPC 就成了"从沙箱里点火"的通道，违反最小权限原则。
- **修复建议**（两选一，推荐前者）：
  1. **主进程记账，忽略渲染层传参**：主进程在 `download()` 成功后记录 `lastDownloadedPath = target`，`open-installer` 不再接受参数，直接对 `lastDownloadedPath` 操作；未下载过则返回 false。路径完全不跨越信任边界，最干净。
  2. **目录白名单校验**：
     ```js
     const allowedDir = path.join(app.getPath('downloads'), SUB_DIR)
     const resolved = path.resolve(String(filePath))
     if (resolved !== path.join(allowedDir, path.basename(resolved))) return false
     // 且强制白名单扩展名：.deb / .exe
     ```

## 🟡 中优先级

### M1. `updater:copy-install-cmd` 未校验入参，剪贴板内容可被渲染层任意指定

- **定位**：`electron/updater.cjs:225-228`
- **问题**：`clipboard.writeText(String(cmd || ''))` 接受任意字符串。危害有限（剪贴板投毒/钓鱼），但同样没必要开放自由写入——命令的构成要素（文件路径）本就在主进程手里。
- **修复建议**：与 H1 方案 1 联动，主进程根据 `lastDownloadedPath` 自行拼 `sudo dpkg -i "<path>"`，IPC 不接受参数（或校验 cmd 必须以 `sudo dpkg -i "` 开头且路径等于 lastDownloadedPath）。

### M2. 快速双击"下载更新"会把 UI 误切成 error 状态（下载实际仍在进行）

- **定位**：`src/useUpdater.js:51-57` + `electron/updater.cjs:118`
- **问题**：第一次 invoke 后、第一条 `downloading` 推送到达前有短暂窗口，`phase` 仍是 `available`，按钮可再次点击；第二次 invoke 返回 `{ok:false, error:'下载已在进行中'}`，hook 立即 `setPhase('error')`——随后进度推送又把 phase 拉回 `downloading`，UI 出现"闪红报错"。
- **修复建议**：hook 里加 `startingRef` 防重入，或 UpdateDialog 在 phase 为 `available/downloading` 时对下载按钮加 `disabled`；同时主进程对"重复下载"的错误推送可改为静默忽略。

### M3. 手动检查绕过缓存且按钮无防抖，易触发 GitHub API 限额（60 次/小时/IP）

- **定位**：`electron/updater.cjs:206-213`（`check({ force: true })`）+ `src/components/Header.jsx`（按钮无 disabled）
- **问题**：每次点击都真实请求 GitHub；`Cache-Control` 60 秒 TTL 只对非 force 生效。连点或高频使用会遇到 HTTP 403 限额，当前错误提示只是通用"响应异常（HTTP 403）"，用户不知所云。
- **修复建议**：
  1. 手动检查改为"TTL 过期才请求，未过期直接回缓存结果"（TTL 已有，去掉 force 即可）；
  2. `checking` 期间禁用 Header 按钮；
  3. 对 403/429 给出专门文案（"检查过于频繁，请稍后再试"）。

### M4. 响应无 content-length 时大小校验被跳过，磁盘可被无限写入

- **定位**：`electron/updater.cjs:152`（`total = Number(...) || asset.size || 0`）与 `174-177`（`if (total > 0 && ...)`）
- **问题**：GitHub 正常会带 content-length，但若走 chunked（代理/异常中间层/被篡改响应），`total` 为 0，完整性校验整体短路，下载无上限写盘。内存无风险（有背压），风险在磁盘。
- **修复建议**：以 `asset.size` 为基准设硬上限，如 `MAX = (asset.size || 500MB) * 1.1`，`received` 超限即 `req.destroy()` 并清理；content-length 与 asset.size 严重不符时也可提前拒绝。

## ⚪ 低优先级

### L1. compareVersions 对预发布号处理粗糙

- **定位**：`electron/updater.cjs:19-29`
- **说明**：`"0.3.0-beta"` 解析为 `0.3.0`（`parseInt("0-beta")=0`），与正式版判等；`"v0.3"`/空串/null 均安全返回 0，无崩溃（重点项已验证）。因 GitHub `/releases/latest` 本身排除 prerelease/draft，实际影响很小。
- **建议**：比较前剥离 `-` 后缀，且带后缀的版本视为低于同号正式版，语义更严谨。

### L2. macOS `activate` 重建窗口后，updater 推送会发往已销毁的旧窗口

- **定位**：`electron/updater.cjs:122-124, 205-249`（闭包捕获 `win`）+ `electron/main.cjs` activate 分支
- **说明**：`send()` 有 `isDestroyed()` 守卫不会崩，但新窗口的渲染层永远收不到状态；且 `registerUpdater` 若重复调用会因 `ipcMain.handle` 重复注册抛异常。当前产品只发 deb/NSIS（window-all-closed 即退出），macOS 仅源码运行场景，故降为低。
- **建议**：`send` 改为取 `BrowserWindow.getAllWindows()[0]`；或 register 时记录 win 引用，在 activate 中更新。

### L3. 响应头取值依赖单元素数组隐式转换

- **定位**：`electron/updater.cjs:152`
- **说明**：Electron `net` 响应头值为 `string[]`，`Number(["12345"])` 恰好等于 12345，属"碰巧正确"。建议：`const cl = res.headers['content-length']; const total = Number(Array.isArray(cl) ? cl[0] : cl) || asset.size || 0`。

### L4. 下载目录旧版本安装包不清理

- **定位**：`electron/updater.cjs:126-130`
- **说明**：每次下载按版本名落盘，多次升级后 `~/Downloads/DocLite/` 会累积旧 deb/exe。建议下载开始前清理同模式旧文件（保留正在下载的这一个）。

### L5. 冒烟截图写入 `__dirname/..`，打包环境下不可写

- **定位**：`electron/main.cjs:117-127`
- **说明**：打包后该路径位于只读的 app 资源目录（asar），截图会失败（已被 try 捕获，不致崩溃）。建议改用 `app.getPath('temp')`。另：smoke 钩子建议显式限制为非打包环境（`!app.isPackaged`）才启用。

### L6. 杂项一致性

- `electron/preload.cjs`、`src/components/Header.jsx`、`DEVLOG.md` 文件末尾缺换行符（git 会报 `\ No newline at end of file`）。
- `src/components/UpdateDialog.jsx:111` 的 `<p` 顶格，缩进错乱（纯格式问题）。
- 下载中弹窗无"取消下载"入口（后台继续下载 + 进度保留属既定设计，可接受；如加取消，主进程需暴露 abort 通道）。

### L7.（增强建议）无哈希完整性校验

- **定位**：`electron/updater.cjs:174-183`（仅 size 校验）
- **说明**：size 相等≠内容正确。GitHub API 不提供 asset 哈希，如想加强：发布时附带 `.sha256` 资产，下载后用 `crypto.createHash('sha256')`（Node 内置，零依赖）比对。属增强项，非本次缺陷。
