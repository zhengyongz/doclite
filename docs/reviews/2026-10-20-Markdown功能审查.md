## 🟡 中优先级

### M1. 超大 Markdown 无阈值降级：主线程同步解析 + 全量 DOM 渲染

- **定位**：`src/components/renderers/MdRenderer.jsx:21-27`；关联 `src/utils/fileHelpers.js:13-14`
- **问题**：`MAX_FILE_SIZE_MB = 100` 对 `SUPPORTED_EXTENSIONS` 内所有格式一视同仁，`.md` 同样可放行 100MB。而 MD 链路是**纯主线程同步**的：
  1. `file.text()` 把 100MB 字节解码为 JS 字符串（UTF-16，内存约 200MB）；
  2. `marked.parse()` 同步遍历整个字符串并拼接输出 HTML（可能再翻倍）；
  3. `DOMPurify.sanitize()` 需要把 HTML 解析成完整 DOM 树（百万级节点）并重新序列化；
  4. 最后 `dangerouslySetInnerHTML` 让 React/Chromium 真实布局这棵巨树。
  四个阶段全部阻塞渲染进程主线程，界面会长时间无响应，内存峰值可达数百 MB～1GB，存在被系统 OOM kill 的可能。同一份内容若以 `.docx` 打开反而有分页与虚拟滚动保护，**MD 是当前唯一"无任何降级手段"的文本格式**。
- **修复建议**（组合使用）：
  1. **按格式区分上限**：`fileHelpers.js` 中为 MD 单独设限，如
     ```js
     export const MAX_FILE_SIZE_MB_BY_EXT = { '.md': 5, '.markdown': 5 }
     // validateFile 内优先取该表，未命中回落到 MAX_FILE_SIZE_MB
     ```
  2. **渲染前字符数兜底**（防止扩展名伪装）：
     ```js
     const HARD_LIMIT = 2_000_000 // 约 2M 字符
     if (text.length > HARD_LIMIT) {
       setHtml(DOMPurify.sanitize(marked.parse(text.slice(0, 200_000) + '\n\n> 文档过大，已截断预览')))
       // 并给出"完整渲染"按钮由用户二次确认
     }
     ```
  3. **可选根治**：把 `marked.parse` 放进 Web Worker（DOMPurify 依赖 DOM 无法进 Worker，但解析阶段是主要耗时来源，可先把字符串→HTML 移出主线程，再回主线程 sanitize）。
- **升级条件**：若产品预期用户会打开 >20MB 的日志/文档型 MD，本项应直接按高优先级处理。

### M2. 非 UTF-8 文件的错误提示永远不可达，实际表现为静默乱码

- **定位**：`src/components/renderers/MdRenderer.jsx:21`（`await currentFile.file.text()`）与 `:33`（错误文案"文件编码可能不受支持（请使用 UTF-8 编码）"）
- **问题**：`Blob.text()` 内部是 `new TextDecoder('utf-8')`（**非** `fatal: true`），遇到非法字节只会替换为 `U+FFFD`，**不会抛异常**。因此 `catch` 分支永远不会因编码问题进入，设计约束中"非 UTF-8 不支持（错误提示引导）"的引导文案形同虚设：用户打开 GBK/GB18030 文档只会看到满屏乱码，且没有任何提示。
- **修复建议**：显式解码并做替换字符检测：
  ```js
  const buf = await currentFile.file.arrayBuffer()
  const text = new TextDecoder('utf-8').decode(buf).replace(/^\uFEFF/, '')
  const bad = (text.match(/\uFFFD/g) || []).length
  if (bad > 0 && bad / text.length > 0.001) {
    // 方案 A（推荐，零依赖）：仍渲染，但顶部插入黄色提示条"检测到疑似非 UTF-8 编码，可能出现乱码"
    // 方案 B（可选增强，Chromium 原生支持 gbk）：new TextDecoder('gbk') 二次尝试，成功率更高
  }
  ```

### M3. Markdown 内的链接点击后毫无反应

- **定位**：`src/components/renderers/MdRenderer.jsx:48`（渲染 `.md-body`）+ `electron/main.cjs:76-78`（`will-navigate` 全量 `preventDefault`）
- **问题**：两处机制叠加导致链接完全失效，且**不是"打开方式不对"，而是彻底无反馈**：
  1. DOMPurify 默认属性白名单**不含 `target`**（已核验 `purify.cjs.js` 552-671 行：`style/type/checked/disabled/href/src` 在列，`target/srcdoc/formaction/xlink:href` 不在列）→ `target="_blank"` 被剥离；
  2. 于是点击 `<a href="https://...">` 触发同窗口导航 → `will-navigate` 直接 `preventDefault()` → 浏览器内核层面取消，页面无任何变化。
  用户看到蓝色下划线链接却点不动，是明确的功能缺陷（也让"文本可选中复制"之外的阅读体验打折）。
- **修复建议**：给 `.md-body` 容器挂事件代理，走 IPC 交给系统浏览器：
  ```jsx
  const onBodyClick = (e) => {
    const a = e.target.closest?.('a[href]')
    if (!a) return
    e.preventDefault()
    const href = a.getAttribute('href') || ''
    if (/^https?:\/\//i.test(href)) window.doclite.openExternal?.(href)   // 新增最小 IPC
    else if (href.startsWith('#')) scrollToAnchor(href)                  // 见 L4
  }
  ```
  主进程侧建议沿用既有 updater 的写法：`shell.openExternal(url)` 且**只放行 http/https**（正则白名单校验，拒绝自定义 scheme）。

### M4. 快速切换文件时存在渲染竞态，可能显示上一个文件的内容

- **定位**：`src/components/renderers/MdRenderer.jsx:14-39`
- **问题**：`renderDoc` 是异步的，切换文件会启动第二个任务，但两个任务共享 `setHtml`。若先打开的 A（大文件、解析慢）晚于后打开的 B 完成，A 的结果会覆盖 B，界面显示 A 的内容而顶部文件名是 B。MD 的解析耗时方差大（几百字节 vs 几 MB），是各渲染器中最容易复现的。
- **修复建议**：
  ```js
  const seqRef = useRef(0)
  const renderDoc = useCallback(async () => {
    const seq = ++seqRef.current
    ...
    if (seq !== seqRef.current) return   // 已被后续请求取代，丢弃结果
    setHtml(...); setStatus('ready'); setPreviewStatus('ready')
  }, [currentFile])
  ```
  （同一模式可顺手补到 DocxRenderer/PptxRenderer，属既有项目级问题，本次不做要求。）

### L6.（可选收紧）`style` 属性默认放行，可做视觉覆盖

- **定位**：`src/components/renderers/MdRenderer.jsx:27`
- **说明**：已核验 DOMPurify 默认属性白名单**包含 `style`**（`purify.cjs.js` 552-671 行），叠加 CSP 的 `style-src 'unsafe-inline'`，恶意 MD 可用 `<div style="position:fixed;inset:0;z-index:99999">` 覆盖界面做伪对话框。因本应用无账号体系、无输入凭据场景，实际危害低；且同页无法发起外联（CSP 已限制 `connect-src`/`img-src`），不构成数据泄露。
- **修复建议**：若追求最严，`sanitize(rawHtml, { FORBID_ATTR: ['style'] })`；代价是 MD 内联样式失效（Markdown 实践中极少使用），可按需取舍。**不建议**改成 `FORBID_TAGS: ['input', 'form']`——任务列表复选框依赖 `input`，会被误伤。
