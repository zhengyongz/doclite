## 阅读约定

- **审查报告**用 `H1/H2`（高）、`M1/M2`（中）、`L1/L2`（低）编号，报告内的「✅ 确认无问题」段落**不入台账**（它们是已验证通过的证明，不是待办）。
- **用户反馈**文档里带 `==问题已经解决==` 标记的条目也已入台账并标为 `已修`，因为「当时标记解决但实际未解决」的情况真实存在（见 B-001、B-008 的注记）。
- 报告中的**修复顺序建议**章节不入台账（那是当时的排序建议，不是问题本身）。
- 审查报告中「已实测确认无问题」的实测方法记录在对应报告原文里，是后续回归的参考。

## 状态回写规则

修复某项后：
1. 在 `../TASKS.md` 把该行状态改为 `已修` 并填关闭版本
2. 在 commit message 末尾写 `Closes: R-0xx`（或 `B-0xx`）
3. **不要**修改本目录下的归档原文 —— 它是当时的快照，保留原貌才能看出判断是如何演进的
